# Публикация на GitHub Pages

Сайт публикуется как **user site** отдельного аккаунта: репозиторий называется
`<username>.github.io`, сайт открывается по `https://<username>.github.io/` —
без подпапки.

## 1. Завести аккаунт по-человечески

Аккаунт проживет год-два, но потерять к нему доступ за неделю до рассылки будет
обидно. Пять минут сейчас:

- Почта, к которой есть доступ у обоих — не рабочая и не университетская.
- 2FA обязательна. **Скачайте recovery codes и положите туда, где найдете через
  месяц.** Аккаунт с аутентификатором на одном телефоне и без кодов
  восстанавливать нечем.
- Если пушить будете с двух ноутбуков — добавьте SSH-ключи обоих в
  Settings → SSH and GPG keys. Передавать друг другу пароль не нужно.

## 2. Репозиторий

Имя должно совпадать с логином **буква в букву**, включая `.github.io`.
При логине `nashasvadba` репозиторий `Nashasvadba.github.io` не заработает.

```bash
cd wedding-invite
python3 configure.py https://<username>.github.io   # проставит адрес везде
git init -b main
git add .
git commit -m "Приглашение"
gh repo create <username>.github.io --public --source=. --push
```

Без `gh` — создать репозиторий руками на github.com, затем:

```bash
git remote add origin git@github.com:<username>/<username>.github.io.git
git push -u origin main
```

## 3. Включить Pages

Settings → Pages → **Source: GitHub Actions**.

Именно Actions, не «Deploy from a branch»: в режиме from-a-branch опубликуется
весь репозиторий, включая `worker/` и `render.py`. Workflow в
`.github/workflows/pages.yml` выкладывает только папку `site/`.

Первый деплой — 1–2 минуты, статус во вкладке Actions.

## 4. Репозиторий придется сделать публичным

На бесплатном тарифе Pages работает только из публичных репозиториев; приватные
— начиная с Pro. Pro по Student Pack привязан к аккаунту с университетской
почтой, на новом аккаунте его нет.

Это не так страшно, как звучит: сайт на Pages публичен в любом случае, даже из
приватного репозитория — приватность прячет историю коммитов, а не то, что
отдает сервер. Решение все равно одно:

| | `guests.json` | Что видно снаружи |
|---|---|---|
| А | коммитим | Список гостей увидит любой, кто знает адрес |
| Б | не коммитим, ссылки вида `?n=Анна&s=2` | Ничего |

На 35 человек, знакомых между собой, А обычно нормально. Для Б допишите
`site/guests.json` в `.gitignore` — сайт без файла не ломается, просто
показывает общее обращение вместо имени.

`robots.txt` и `noindex` уже стоят. У user site `robots.txt` лежит в корне и
действительно работает — в варианте с подпапкой действовал бы только метатег.
Но Pages — это хостинг, а не защита: ссылка не секретная, просто неизвестная.

## 5. Свой домен (по желанию)

`<username>.github.io` уже читается прилично, так что домен теперь скорее
украшение. Если хочется — около 200 ₽/год на reg.ru или nic.ru:

1. Settings → Pages → Custom domain → вписать домен. Появится файл `CNAME` —
   после этого `git pull` и переложите `CNAME` в папку `site/`, иначе workflow
   затрет его при следующем деплое.
2. У регистратора:
   - `A` для голого домена → `185.199.108.153`, `185.199.109.153`,
     `185.199.110.153`, `185.199.111.153`
   - `CNAME` для `www` → `<username>.github.io.`
3. Через полчаса вернуться в Settings → Pages и включить **Enforce HTTPS**.
4. `python3 configure.py https://вашдомен.ru`, пересобрать ссылки гостям.

## 6. og.jpg

Файл `site/og.jpg`, 1200×630. Рендерится из той же карточки:

```bash
cd card
python3 - <<'EOF'
from playwright.sync_api import sync_playwright
import pathlib
html = pathlib.Path("card.html").read_text(encoding="utf-8")
for k, v in {"GUEST":"", "NAME_A":"Мария", "NAME_B":"⟨Имя⟩", "DATE":"17 октября 2026",
             "TIME":"", "TEMPLE":"", "ADDRESS":"", "NOTE":"", "PHOTO_URL":""}.items():
    html = html.replace("{{"+k+"}}", v)
with sync_playwright() as p:
    b = p.chromium.launch()
    pg = b.new_page(viewport={"width":1200,"height":630})
    pg.set_content(html, wait_until="networkidle"); pg.wait_for_timeout(400)
    pg.screenshot(path="../site/og.jpg", type="jpeg", quality=88)
    b.close()
EOF
```

**Залейте og.jpg до первой рассылки.** WhatsApp и Telegram кешируют превью
надолго: если первый гость откроет ссылку без картинки, у него она такой и
останется.

## 7. Чек-лист перед рассылкой

- [ ] `grep -o '⟨[^⟩]*⟩' site/index.html` — пусто
- [ ] Открыть сайт с телефона, не с десктопа
- [ ] Отправить ссылку самой себе в WhatsApp — развернулось ли превью
- [ ] Открыть персональную ссылку `?g=…` — подставилось ли имя и число мест
- [ ] Отправить тестовый RSVP и убедиться, что дошел
- [ ] Recovery codes от аккаунта сохранены
